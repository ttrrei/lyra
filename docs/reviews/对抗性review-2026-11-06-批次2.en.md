### Vulnerability 1: [Critical Architecture Deadlock] B9 / I17 OCI global immutability rule breaks direction evolution (`hypothesis.md` / `lessons.md`) push

* **Affected Files**: [`docs/proposals/oci-alpha-layout.md`](file:///home/ubuntu/work/lyra/docs/proposals/oci-alpha-layout.md#L427) (B9), [`docs/decisions/0001-repo-and-oci-split.md`](file:///home/ubuntu/work/lyra/docs/decisions/0001-repo-and-oci-split.md#L82) (I17), [`docs/requirements.md`](file:///home/ubuntu/work/lyra/docs/requirements.md#L201) (R12).
* **Vulnerability Description**:
  * Rule B9 and invariant I17 stipulate: "**Files on OCI are immutable (same path + same sha256 is idempotent; different sha256 raises an error)**", and test suite 0001 includes `test_push_rejects_sha_mismatch`.
  * Simultaneously, R12 explicitly defines `hypothesis.md` within a direction as containing mutable state transitions (active/paused/killed) and an append-only modification history; `lessons.md` is an append-only log (one section per version); and `index/*.json` is dynamically derived and updated as new strategies and runs appear.
* **Deadlock Scenario**:
  * Initial phase: A user or AI pushes the initial version `v01` of the `trend_continuation` direction; `lessons.md` is uploaded to OCI, recording hash $H_1$.
  * Iteration phase: Based on diagnosis of `v01`, the AI or user appends lessons from candidate `v02a` to local `lessons.md`, changing the hash to $H_2$. They then run `lyra push-direction trend_continuation`.
  * Fatal Collision: The remote path `.../trend_continuation/lessons.md` on OCI already exists, but hash $H_2 \neq H_1$. Under B9 / I17, this push is rejected as a "data drift error"! The entire direction evolution log becomes unpushable to OCI!
* **Red-Team Verdict**: **Critical Vulnerability**. B9 and I17 conflate immutable operational data (Data/Runs/vNN.yaml) with append-only metadata (Hypothesis/Lessons/Index).
* **Remediation**:
  Must partition paths into two distinct lifecycle tiers:
  1. **Strictly Immutable Paths**: `data/**`, `runs/**`, `strategies/**/v*.yaml`, `alpha/features/*.py` (code and numerical data are never overwritten).
  2. **Append-Only / Mutable Metadata Paths**: `strategies/**/hypothesis.md`, `strategies/**/lessons.md`, `index/*.json` (overwriting allowed when content is a superset or represents version progression).

### Vulnerability 2: [Semantic Conflict & AI Hallucination Risk] "Parameter modification / mutation" directly contradicts I8 / R2 "Fixed Feature Parameters"

* **Affected Files**: [`docs/ACTION_LOG.md`](file:///home/ubuntu/work/lyra/docs/ACTION_LOG.md#L49) (#22, #49), [`docs/proposals/oci-alpha-layout.md`](file:///home/ubuntu/work/lyra/docs/proposals/oci-alpha-layout.md#L215) (§2.3), [`AGENTS.md`](file:///home/ubuntu/work/lyra/AGENTS.md#L11) (Non-negotiables), [`docs/hld.md`](file:///home/ubuntu/work/lyra/docs/hld.md#L199) (I8).
* **Vulnerability Description**:
  * `ACTION_LOG.md` entry #22 and the version tree specification state: "Crossover/mutation is completely in the hands of the AI strategy finder: what to take, how to synthesize (whole blocks / parameter-by-parameter / **modifying parameters**) is entirely free for the AI to decide without framework constraints."
  * However, `AGENTS.md` and invariant I8 state: "**Feature parameters are fixed. New features are registered, not re-parameterized. No parameter sweeps.**"
* **Potential Risk**:
  * Given that the AI is a first-class writer, feeding context containing "freedom to modify parameters" will predictably induce LLM hallucinations where the model attempts to alter feature definitions in YAML (e.g., rewriting `sma_alignment_6_24` to `sma_alignment_7_25`, or altering `rsi_14` to `rsi_17`).
  * Any YAML generated this way will fail during `lyra validate` because the feature is unregistered, burning LLM context and API budget.
* **Red-Team Verdict**: **Major Severity**. Dangerous ambiguity in language.
* **Remediation**:
  Explicitly disambiguate in R12, ACTION_LOG, and proposals: The AI's mutation freedom is **strictly restricted to strategy-level threshold and temporal parameters** (such as `held_for.bars`, `within.bars`, comparison operators, numerical thresholds); **modifying registered feature names or underlying feature parameters is strictly prohibited (adhering to I8)**.

### Vulnerability 3: [Version Tree Lifecycle Gaps] Cross-generation crossover semantics undefined, naming collisions, and infinite branching circumventing kill criteria

* **Affected Files**: [`docs/requirements.md`](file:///home/ubuntu/work/lyra/docs/requirements.md#L207) (R12), [`docs/proposals/oci-alpha-layout.md`](file:///home/ubuntu/work/lyra/docs/proposals/oci-alpha-layout.md#L219) (§2.3).
* **Vulnerability Description**:
  * **Gap 3.1 (Cross-generation crossover undefined)**: Version naming is specified as `v<generation><branch-suffix>`. In evolutionary strategy research, crossing parents from different generations (e.g., crossing a robust baseline `v02a` with a recent breakout branch `v04b`) is standard. Current docs do not specify which generation the child belongs to (Generation 3? Generation 5?).
  * **Gap 3.2 (Same-parent multiple crossover collision)**: If an AI explores two different synthesis schemes between the same pair of parents `v03a` and `v03b` (e.g., Scheme 1 crosses entry rules, Scheme 2 crosses exits), both would be named `v04ab.yaml`, overwriting each other.
  * **Gap 3.3 (Infinite branching evading kill criteria)**: R12 dictates that single branch failure triggers a `prune`, and kill criteria apply only when "all active branches fail for N consecutive rounds". Because the framework sets no cap on concurrent active branches, an automated AI could spawn endless micro-variations (`v02c`, `v02d`, `v02e`...) to indefinitely evade kill criteria, creating zombie directions that perpetually drain budget.
* **Red-Team Verdict**: **Moderate Severity**. Evolutionary mechanics lack programmatic rigor.
* **Remediation**:
  1. Define cross-generation child generation as $\max(\text{parent generations}) + 1$.
  2. Permit an index or mutation variant suffix (e.g., `v05ab_1.yaml` or hash suffix).
  3. Enforce an **active branch cap** per direction (e.g., max 3-4 concurrent active branches); branches beyond the cap must be pruned.

### Vulnerability 4: [Execution Engine Interface Gap] Disconnect between sparse SQL signals and trade engine 2% adverse price stop calculations

* **Affected Files**: [`docs/hld.md`](file:///home/ubuntu/work/lyra/docs/hld.md#L97) (§2.3, §2.4), [`docs/requirements.md`](file:///home/ubuntu/work/lyra/docs/requirements.md#L78) (R4).
* **Vulnerability Description**:
  * HLD states: `compiler` compiles YAML to DuckDB SQL; `run` executes SQL and drives the trade state machine bar-by-bar.
  * Invariant I3 mandates: Whenever price moves adversely by 2% relative to entry during holding, exit triggers before next open.
  * **Interface Disconnect**: If DuckDB SQL only outputs rows where `signal == True`, the Python trade state machine will receive zero data for the tens or hundreds of intermediate bars while a position is held! Without intermediate high/low prices, the trade engine cannot determine if the 2% adverse stop was breached!
* **Red-Team Verdict**: **Moderate Severity**. Directly impacts the architectural validity of upcoming decisions 0004 and 0005.
* **Remediation**:
  Clarify data flow in HLD and upcoming decision docs 0004/0005:
  * **Option A (Full streaming replay)**: SQL annotates predicates across the complete Parquet wide table; Python trade engine streams all bars, tracking order state and bar-by-bar extremes.
  * **Option B (SQL window aggregation)**: SQL computes holding period extremes via range joins.
  * *Option A recommended* to keep DuckDB focused on pure analytical compute and Python on deterministic state transitions.

### Vulnerability 5: [OCI Local Mirror Boundary Omission] B13 isolates data and strategies outside repo, but omits custom features `alpha/`

* **Affected Files**: [`docs/proposals/oci-alpha-layout.md`](file:///home/ubuntu/work/lyra/docs/proposals/oci-alpha-layout.md#L429) (B13), [`config/config_example.yml`](file:///home/ubuntu/work/lyra/config/config_example.yml#L13).
* **Vulnerability Description**:
  * B13 states: "OCI mirrors (`data/`, `strategies/`, `runs/`) resolve outside the repository to `~/.lyra/<workspace>/…` by default."
  * However, OCI also stores `alpha/features/*.py` (custom alpha features, contracts, tests).
  * In `config_example.yml`, the `local:` block only specifies `data`, `strategies`, `runs`, and `tmp`; `alpha` is missing.
  * If a user pulls custom features via `lyra pull` or authors them locally without a prescribed mirror path, they are likely to create `./alpha/` directly inside the git working tree, triggering a B1 violation.
* **Red-Team Verdict**: **Moderate Severity**. Boundary isolation missed custom features.
* **Remediation**:
  Add `alpha: "alpha"` under `local:` in `config_example.yml`, and amend B13 to explicitly include `alpha/` within the `~/.lyra/<workspace>/alpha/` external sandbox.

### Vulnerability 6: [Instrument Pool & Temporal Cost Ambiguity] Missing 21-instrument canonical definition and weekend financing calendar days undefined

* **Affected Files**: [`docs/requirements.md`](file:///home/ubuntu/work/lyra/docs/requirements.md#L91) (R1, R4, R8), [`config/config_example.yml`](file:///home/ubuntu/work/lyra/config/config_example.yml#L33).
* **Vulnerability Description**:
  * R1 covers forex, metals, oil, and equity indices; R8 specifies acceptance on "21 instruments H1 full run". Yet no document lists the canonical symbols for these 21 instruments (e.g., is gold `XAU_USD` or `GOLD`? is oil `BCO_USD` or `WTICO_USD`?).
  * Cost configuration specifies `financing_per_day: 0.0001` (fraction per elapsed day). In live CFD/forex trading, holding over a weekend incurs 3 days of swap/financing. The docs do not define whether "elapsed day" is physical calendar days (`exit_time - entry_time`) or trading bars. Ambiguity here causes non-deterministic backtest returns, violating R8.
* **Red-Team Verdict**: **Minor Severity**. Specification ambiguity affecting bit-for-bit reproducibility.
* **Remediation**:
  Append a canonical 21-instrument symbol table in HLD or Requirements appendix; specify that financing strictly computes elapsed physical calendar days via UTC timestamps (including weekends).
