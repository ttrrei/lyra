## Review Detail

### A1 Stale derived-cache hole (valid, real defect → fixed)

**Attack surface**: idempotency is only defined at the raw download layer
(I20). Re-run semantics of the derived layers (`raw_csv` →
`all_data.parquet` → `ohlcv_5m/1h`) are undefined. Scenario: ① user
deletes `all_data.parquet` to rebuild → `lyra pull` skips all downloads
(raw idempotent), and if clean also "skips when output exists" → the user
can never get bronze back; ② subtler: `all_data.parquet` is corrupted
(disk / killed process) → same outcome, and **no error**, silent loss.

**Settlement (0002 v0.3 §3.1/§3.3)**: **only the raw download layer skips
on idempotency; clean and aggregate recompute and overwrite their outputs
on every `lyra pull`** (no "output exists → skip"). Rationale:
bronze/5m/1h are all deterministic functions of the raw data (I18);
recomputation costs ≈ one DuckDB scan, while "output exists → skip"
introduces a semantic hole far larger than the gain; "raw unchanged →
outputs row-identical" follows directly from I18.

### A2 Bronze schema not explicitly defined (valid → fixed)

**Attack surface**: 0002 v0.2 only says "required columns
`instrument,time,is_complete` + optional mid/bid/ask"; the bronze output
column set is **implicit**. 0003 (feature builder)'s input contract must
be deterministic. And `is_complete` is clean's filter condition — keeping
it in bronze is a dead column.

**Settlement (0002 v0.3 §3.3)**: bronze 1m Parquet schema = **the union of
input CSV columns**, where:
- always present: `instrument, time, volume, mid_o, mid_h, mid_l, mid_c`;
- source-dependent: `bid_*, ask_*` (kept when the moneta sources have them);
- **`is_complete` is NOT included** (consumed by clean; true for every
  bronze row, carries no information).
