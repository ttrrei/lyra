## Key fix details

### A1 + A2 (the core of this batch)

**A1** is the textbook "fixture-untestable fatal" case. Batch-04's clean was
"all green" on a 70-row 1m fixture but `csv.DictReader` row-by-row Python
parsing is simply infeasible at 48.8M rows (stalls in practice). The rewrite
does filter + dedupe + write in one DuckDB `COPY` — 48M rows ≈ 15 min with
**flat memory** (DuckDB streams, never materializes the full table).

**A2** is subtler: it's not "wrong code" but a **contract that real data
violates**. The original I22 ("every consecutive pair exactly 1m apart")
implicitly assumed *contiguous* 1m — but real market data has weekends,
holidays, and no-trade minutes, so bars are always missing. 731,078 gaps ≥5m
prove it. The refined criterion (**minimum** gap ≈1m) separates "1m
resolution with gaps" (legit) from "5m/1h native resolution" (reject) — which
was I22's actual intent all along.

### Verification (real data)

- `lyra pull` end-to-end success: 163 raw zips → 183 CSVs → **bronze 48,846,896 rows** → **5m 9,986,167 bars** → **1h 838,272 bars** (15m51s)
- 21 instruments, all min inter-bar gap = **1.00 min** (I22 native-resolution criterion → 0 violations)
- 5m `n_bars` histogram: peaks at n_bars=5 (9,350,811 bars) + partial windows n_bars=1..4 (~630k, the gaps) — **I21 partial-window flagging works**
- XAU_USD span **2020-01-02 → 2026-11-06** (6 full years)
- three Parquet schemas correct: bronze 15 cols (incl. bid/ask), 5m/1h 8 cols (incl. `n_bars`), `time` all `TIMESTAMPTZ`
- fixture suite **24 passed** + pyflakes clean (real-data fixes didn't break fixture coverage)
