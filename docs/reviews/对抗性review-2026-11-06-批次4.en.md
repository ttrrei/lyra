## Key fix detail (A1, highest value)

The original code:

```python
# ❌ before: base64(24) vs hex(32) compared as strings → always False → always re-download
def _md5_matches(local, remote_md5):
    ...
    return _md5_of_file(local) == str(remote_md5).lower()
```

Because PAR **listing** returns base64 and the **download** Etag returns hex,
the two encodings of the *same* file never string-match, so the "skip on md5
hit" path was **unreachable from day one** — I20 silently degraded to
"size fallback", which itself mis-fires when contents change length-identically.
moneta's `extract_oci.py` hit exactly this pit and did size comparison only.

After the fix (`oci_client.py`):

```python
# ✅ after: normalize both to hex before comparing
def _to_md5_hex(remote_md5: str) -> str | None:
    v = remote_md5.strip().strip('"')
    if len(v) == 32 and all(c in "0123456789abcdefABCDEF" for c in v):
        return v.lower()                      # already hex
    if len(v) in (24, 25):                    # base64 → 16-byte digest
        digest = base64.b64decode(v + "=" * (-len(v) % 4))
        if len(digest) == 16:
            return digest.hex()
    return None
```

Plus **pure-function-level** verification (base64 form / hex form / wrong
value / None) and **integration-level** verification (`test_oci_download_md5_mismatch`:
stale local ⇒ re-download with new bytes; fresh local ⇒ skip with exactly one
extra list request).
