### Defect 1: [Critical Data Corruption & Column Drop] First-File Column Sniffing Silently Bypasses DQ2 and Drops Quote Columns Under Multi-CSV Inputs

* **Affected Files**: [`lyra/clean.py`](file:///home/ubuntu/work/lyra/lyra/clean.py#L197-L212) (`clean_csv_to_bronze`), [`lyra/clean.py`](file:///home/ubuntu/work/lyra/lyra/clean.py#L265-L288) (`clean_csv_to_bronze_parquet`).
* **Severity**: **Critical**
* **Code in Reality**:
  ```python
  # lyra/clean.py:265-288
  first = sorted(csv_dir.rglob("*.csv"))[0]
  cols = {
      r[0].lower()
      for r in con.execute(
          "DESCRIBE SELECT * FROM read_csv(?, header=TRUE, auto_detect=TRUE) LIMIT 1",
          [str(first)],
      ).fetchall()
  }
  missing = [c for c in REQUIRED_INPUT if c not in cols]
  if missing:
      raise CleanInputError(...)
  present = {c for c in PAYLOAD if c in cols}
  inner = _clean_sql(csv_dir, present)
  _assert_quality(con, inner, present)
  out_cols = ["instrument", "time"] + [
      c for c in ALWAYS_PRESENT if c not in ("instrument", "time")
  ]
  for c in sorted(present):
      if c not in out_cols:
          out_cols.append(c)
  select = ", ".join(out_cols)
  con.execute(f"COPY (SELECT {select} FROM ({inner}) t) TO {_quote(out_path)} (FORMAT PARQUET)")
  ```
* **One-Sentence Evidence**:
  `present` is probed solely from `sorted(csv_dir.rglob("*.csv"))[0]`; when flat historical CSVs (mid-only) coexist with nested OANDA CSVs (with quotes), the first file lacks quote columns, causing DQ2 validation rules to completely vanish, silently writing inverted spread data to bronze while DuckDB `COPY` silently discards all quote columns from subsequent CSVs.
* **Impact Analysis**:
  1. **DQ2 Rule Disappearance**: If a directory contains legacy flat CSVs like `01_flat.csv` (which only have mid prices), it is sorted first. `present` contains no `bid_*` or `ask_*` columns. In `_quality_checks`, `point_clauses` evaluates to empty, and `bad_spread` is never injected into `checks`. Even if an OANDA backfill CSV in a subdirectory has inverted spreads (`ask_o < bid_o`), `_assert_quality` never checks spreads!
  2. **Dirty Data Written & Quote Columns Discarded**: `out_cols` selects only columns in `present`. DuckDB `COPY` projects only `ALWAYS_PRESENT + present`, completely dropping all `bid_*` and `ask_*` columns from OANDA CSVs while writing the corrupted rows into bronze parquet, violating invariant I23.
  3. **Silent Missing Column Bypass**: `REQUIRED_INPUT` is also only checked against `first`. If a subsequent CSV lacks `mid_l`, DuckDB's `union_by_name` fills `mid_l` with `NULL`. SQL comparisons against NULL in DQ1 evaluate to `NULL` (falsy), allowing rows with missing required columns to bypass DQ1 and enter bronze.
* **Minimal Reproduction**:
  ```python
  import tempfile, duckdb
  from pathlib import Path
  from lyra.clean import clean_csv_to_bronze_parquet

  with tempfile.TemporaryDirectory() as td:
      p = Path(td)
      # 01.csv contains only mid (sorted first)
      (p / "01.csv").write_text("instrument,time,volume,mid_o,mid_h,mid_l,mid_c,is_complete\nX,2020-01-01T00:00:00Z,1,10,12,9,11,True\n")
      # 02.csv from OANDA contains quotes but ask_o (5) < bid_o (10) inverted
      (p / "02.csv").write_text("instrument,time,volume,mid_o,mid_h,mid_l,mid_c,bid_o,bid_h,bid_l,bid_c,ask_o,ask_h,ask_l,ask_c,is_complete\nY,2020-01-01T00:01:00Z,1,10,12,9,11,10,12,9,11,5,12,9,11,True\n")
      out = p / "out.parquet"
      clean_csv_to_bronze_parquet(p, out)
      con = duckdb.connect()
      cols = [r[0] for r in con.execute("DESCRIBE SELECT * FROM read_parquet(?)", [str(out)]).fetchall()]
      assert "bid_o" not in cols  # Evidence: OANDA quote columns dropped, inverted spread not caught
  ```

### Defect 2: [Critical Time Arithmetic Crash] Backfill Triggered in Last Minute of Month Crashes with `m_start > m_end`

* **Affected Files**: [`lyra/oanda.py`](file:///home/ubuntu/work/lyra/lyra/oanda.py#L365-L367) (`backfill_window`), [`lyra/oanda.py`](file:///home/ubuntu/work/lyra/lyra/oanda.py#L184) (`fetch_candles`).
* **Severity**: **Critical**
* **Code in Reality**:
  ```python
  # lyra/oanda.py:365-367
  m_end = next_month_start - timedelta(minutes=1)
  m_start = max(m_start, start)
  m_end = min(m_end, end)
  ```
* **One-Sentence Evidence**:
  `backfill_window` naively clamps month boundaries using `next_month_start - timedelta(minutes=1)`; when `time_from` falls within the last minute of a month (e.g. `2020-01-31T23:59:30Z`), `m_start > m_end`, calling `fetch_candles` crashes immediately with `OandaError("--to must be at or after --from")`.
* **Impact Analysis**:
  1. `next_month_start - timedelta(minutes=1)` computes `m_end` as `23:59:00Z`.
  2. If `start` is between `23:59:01Z` and `23:59:59Z`, `m_start` is set to `start`, while `m_end` is `23:59:00Z`.
  3. Calling `fetch_candles` with `time_from="23:59:30Z"` and `time_to="23:59:00Z"` hits line 184: `if end < start: raise OandaError` and aborts execution.
  4. Furthermore, if granularities finer than M1 are configured (`S5`, `S10`, `S15`, `S30`), subtracting a full 1 minute permanently truncates the last 59 seconds of every month.
* **Minimal Reproduction**:
  ```python
  import tempfile
  from pathlib import Path
  from lyra.oanda import backfill_window

  with tempfile.TemporaryDirectory() as td:
      backfill_window(
          Path(td), "GBP_USD",
          "2020-01-31T23:59:30Z", "2020-02-01T00:05:00Z",
          token="dummy_token", dry_run=False,
      )
      # Crashes: lyra.oanda.OandaError: --to must be at or after --from
  ```

### Defect 3: [Major False Resume Boundary] Partial-Month Backfill Causes Subsequent Full-Month Backfills to Silently Skip

* **Affected Files**: [`lyra/oanda.py`](file:///home/ubuntu/work/lyra/lyra/oanda.py#L368-L372) (`backfill_window`).
* **Severity**: **Major**
* **Code in Reality**:
  ```python
  # lyra/oanda.py:368-372
  out = _chunk_path(csv_root, instrument, month, granularity)
  if out.exists() and out.stat().st_size > 0 and not force:
      log(f"[{instrument}] month {month:%Y-%m} already present ({out.name}); skipping.")
      written.append(out)
      continue
  ```
* **One-Sentence Evidence**:
  The resume logic only checks if the monthly file exists and is non-empty (`out.exists() and out.stat().st_size > 0`); a partial-window backfill creates a file with that name, causing subsequent backfills covering the full month to falsely skip, leaving a permanent silent data gap.
* **Impact Analysis**:
  1. `_chunk_path` generates month-start filenames: `{instrument}_{granularity}_{YYYYMM}01T000000Z.csv`.
  2. If a user previously fetched a partial range (e.g., `2020-01-01` to `2020-01-02`), or if an earlier process was interrupted, a non-empty CSV file with only a couple days of data exists on disk.
  3. When a later command requests a full month backfill (`--from 2020-01-01 --to 2020-01-31`), `backfill_window` detects the file exists with `st_size > 0` and skips it.
  4. The remaining ~29 days of candles are never downloaded, and the CSV file bears a month-wide filename, falsely signaling that the month is complete.
* **Minimal Reproduction**:
  ```python
  import tempfile
  from pathlib import Path
  from lyra.oanda import backfill_window

  with tempfile.TemporaryDirectory() as td:
      root = Path(td)
      partial_file = root / "GBP_USD" / "GBP_USD_M1_20200101T000000Z.csv"
      partial_file.parent.mkdir(parents=True)
      partial_file.write_text("instrument,time,volume,mid_o,mid_h,mid_l,mid_c,is_complete\nGBP_USD,2020-01-01T00:00:00Z,1,1,1,1,1,True\n")

      # User attempts to fetch the full month
      backfill_window(
          root, "GBP_USD",
          "2020-01-01T00:00:00Z", "2020-01-31T23:59:00Z",
          token="dummy_token", dry_run=False,
      )
      # File was skipped; row count remains 1
      assert partial_file.read_text().count("\n") == 2
  ```

### Defect 4: [Major Boundary Leak] Non-Matching Partial-Quote Points Cause DQ2 Spread Rules to Silently Vanish

* **Affected Files**: [`lyra/clean.py`](file:///home/ubuntu/work/lyra/lyra/clean.py#L117-L124) (`_quality_checks`).
* **Severity**: **Major**
* **Code in Reality**:
  ```python
  # lyra/clean.py:117-124
  point_clauses = [
      f"bid_{p} IS NOT NULL AND ask_{p} IS NOT NULL AND ask_{p} < bid_{p}"
      for p in ("o", "h", "l", "c")
      if f"bid_{p}" in present and f"ask_{p}" in present
  ]
  if point_clauses:
      checks["bad_spread"] = " OR ".join(point_clauses)
  return checks
  ```
* **One-Sentence Evidence**:
  `_quality_checks` matches strictly on identical point names (`f"bid_{p}" in present and f"ask_{p}" in present`); if a partial quote input carries staggered points (e.g. only `bid_l` and `ask_h`), `point_clauses` is empty, completely dropping `bad_spread` and allowing bars where `ask_h < bid_l` (physically impossible inverted spread across the entire bar) to pass.
* **Impact Analysis**:
  1. Under partial-quote inputs, if the source data only carries `bid_l` and `ask_h`, testing $p \in \{o, h, l, c\}$ finds no point where both `bid_p` and `ask_p` exist in `present`.
  2. `point_clauses` is empty, so DQ2 spread validation is omitted entirely.
  3. Even if a row has `ask_h = 5.0` and `bid_l = 10.0` (where every ask in the bar was lower than every bid in the bar), DQ2 never triggers.
  4. In addition, DQ1 and DQ2 lack `isfinite()` checks for IEEE 754 `NaN`. In DuckDB, comparison with NaN evaluates to `False`, allowing `NaN` quotes to silently bypass DQ1 and DQ2.
* **Minimal Reproduction**:
  ```python
  import tempfile
  from pathlib import Path
  from lyra.clean import clean_csv_to_bronze_parquet

  with tempfile.TemporaryDirectory() as td:
      p = Path(td)
      # Input has bid_l and ask_h, no matching point pair; ask_h(5) < bid_l(10)
      (p / "bad.csv").write_text("instrument,time,volume,mid_o,mid_h,mid_l,mid_c,bid_l,ask_h,is_complete\nX,2020-01-01T00:00:00Z,1,10,12,9,11,10,5,True\n")
      out = p / "out.parquet"
      clean_csv_to_bronze_parquet(p, out)
      assert out.exists()  # Silently passes; DataQualityError not raised
  ```

      api_token: str = ""
      host: str = "api-fxpractice.oanda.com"

* **One-Sentence Evidence**:
