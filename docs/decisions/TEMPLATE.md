# 决策文档模板

> **English**: [TEMPLATE.en.md](./TEMPLATE.en.md)
>
> 每个 Lyra feature 必须配一份决策文档。复制本模板，填完再写代码。
> 决策文档是**只增不删**的（历史决策不删，只在文末"修订记录"加新行）。

## 元信息

| 字段 | 值 |
|---|---|
| ID | `NNNN`（4 位零填充，从 0002 起递增） |
| 标题 | `<feature 名>` |
| 状态 | 提案 / 已批准 / 已实现 / 已废弃 |
| Owner | `ttrrei` |
| 创建日期 | `YYYY-MM-DD` |
| 相关提案 | `docs/proposals/<name>.md`（如有） |
| 相关需求 | `docs/requirements.md` §R? |
| 相关 HLD | `docs/hld.md` §? |
| 取代 | `NNNN`（如有） |

## 1. 问题

用 1-3 句话回答：**这个 feature 解决什么问题？**
（不是"我们要做什么"，是"我们为什么要做"。）

## 2. 背景

- 现状是什么？（moneta / nova 怎么做的，为什么不够）
- 相关的历史决策是什么？（链接到旧决策文档）
- 相关的开放问题是什么？（链接到 `docs/open-questions.md`）

## 3. 方案

### 3.1 做什么

- 具体的接口 / CLI / 文件布局。
- 代码层面要新增 / 修改 / 删除哪些文件。

### 3.2 不做什么

- 明确列出**本 feature 不做**的事情（防止 scope creep）。
- 如果某个"看起来相关"的事情不在本 feature 里，说明为什么
  （拆到哪个 feature 里做）。

### 3.3 边界

- 输入 / 输出的契约。
- 与 OCI 的边界（读什么 / 写什么 / 凭证从哪来）。
- 与 alpha 的边界（是否碰 alpha 文件 / 是否影响 alpha 语义）。
- 与 moneta / nova 的兼容边界（是否向后兼容 / 是否兼容 moneta 的
  332 策略）。

## 4. 不变量

本 feature 必须**持续保证**的不变量。
引用 `docs/hld.md` §4 的 I1-I14，或新增新的不变量。

| # | 不变量 | 来源 |
|---|---|---|
| I? | ... | 本 feature 新增 / I1 (HLD §4) |

## 5. 测试

必须覆盖的测试场景（pytest 用例名 + 一句话描述）：

| 测试 | 场景 |
|---|---|
| `test_<feature>_<case>` | <一句话> |

## 6. 回滚

如果本 feature 上线后出问题，**怎么回滚**？
- 代码层面：revert 哪个 commit / 哪几个文件。
- 数据层面：OCI 上的文件要不要删 / 本地 `data/` 要不要清。
- 兼容性：回滚后 moneta / nova 的策略还能不能跑。

## 7. 审批

- [ ] 用户 review
- [ ] AI review（另一模型）
- [ ] 测试全绿
- [ ] 332 策略回归通过（如适用）
- [ ] OCI 端到端跑通（如涉及 OCI）

## 8. 修订记录

| 日期 | 版本 | 变更 |
|---|---|---|
| YYYY-MM-DD | 0.1 | 初稿。 |
